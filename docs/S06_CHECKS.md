# S06 — подтверждение обработки данных TaskSpace

## Свойство, цепочка и выбранный участок

Выполнен перенос метода S06 на собственный продукт: **подтверждение уже обеспеченного свойства**, а не исправление специально добавленной уязвимости. Участок — создание задачи и сдача результата через реальный ASP.NET pipeline и файловую SQLite.

Основная цепочка: **T-06 → SR-08, SR-10 → D-04 → `Database_failure_rolls_back_submission_and_is_a_sanitized_500` → фактический вывод и TRX**. Невалидные данные и сбой хранения не должны оставлять частично изменённую задачу или историю. Некорректный ввод отличается от внутренней ошибки: 400 и 500 соответственно, без внутренних деталей в ответе.

Дополнительная проверка изоляции: **T-02 → SR-03 → D-02 → `Ordinary_and_sql_looking_text_create_tasks_without_changing_foreign_data`**: другая команда не получает созданные задачи, а данные её собственной команды не меняются.

Ссылки: [модель угроз](../threat-model.md), [SR-08/SR-10 и остальные требования](../security-requirements.md#требования), [D-04](../security-design.md#d-04-атомарный-переход-и-неизменяемая-история), [тесты S06](../tests/TaskSpace.Api.Tests/DataHandlingEvidenceTests.cs).

## Механизм и отсутствие исправляющего патча

- [Program.cs](../src/TaskSpace.Api/Program.cs) включает выбрасывание исключений при некорректном связывании входных данных и общий обработчик ошибок перед маршрутами.
- [ApiErrorMiddleware](../src/TaskSpace.Api/Services/ApiErrorMiddleware.cs) различает ошибку запроса/JSON и внутренний сбой, возвращает общий JSON без stack trace и пути БД, добавляет no-store.
- [WorkflowService](../src/TaskSpace.Api/Services/WorkflowService.cs) выполняет условное обновление и запись истории в одной транзакции. Ошибка вставки до commit откатывает статус и версию.
- [TaskEndpoints](../src/TaskSpace.Api/Endpoints/TaskEndpoints.cs) сохраняет введённые строки через EF Core, определяет автора по сессии и проверяет команду. Чтение использует фильтр членства D-02.

В исследованном участке нарушение не обнаружено. Производственный код не изменялся. Добавлены проверки и первичные результаты; сценарий падения «до исправления» здесь не требуется. SQLite-триггер существует только в отдельной тестовой базе и имитирует отказ хранения, а не внедряет уязвимость в приложение.

## Версия и условия

- Дата: 2026-10-23; macOS/Darwin arm64, .NET SDK 10.0.401, runtime 10.0.12.
- База исходного дерева: `9be6c97` (полный hash в [base-commit.txt](evidence/s06/base-commit.txt)); добавленные тесты сохранены коммитом `b06ad4dd3319f80d701b9924edd2d951c30183e0`.
- Полный набор выполнен на `b06ad4d`; адресный прогон выполнен непосредственно перед фиксацией идентичного содержимого тестов. Изменения после этого — протокол и сохранённый вывод, не код.
- Production и Development проверяются отдельно. Каждый случай создаёт новую файловую SQLite через [TestApp](../tests/TaskSpace.Api.Tests/TestApp.cs); рабочая база не используется.
- Alice: автор команды A; Bob: исполнитель задачи 1, версия 1; Dave: участник команды B. Сессии получаются обычным входом и не печатаются в результатах.
- Снимок для «без изменений» включает пользователей, команды, членство, задачи, сдачи, решения и сессии. Служебный триггер создан до первого снимка.

## Запросы, ожидания и фактические результаты

Запросы ниже выполняет HttpClient/WebApplicationFactory; это HTTP-проверка ASP.NET в процессе с реальной SQLite, не отдельный сетевой сервер.

| Проверка | Условия и запрос | Ожидание | Фактически |
| --- | --- | --- | --- |
| Повреждённый JSON | Alice; POST `/api/teams/1/tasks`, тело `{ not valid json`; Production и Development | 400, `{"error":"Некорректный запрос."}`, без деталей и изменений базы | Passed, 2 случая |
| Неверный тип | Тот же метод, `{"title":"s06-private-input","description":"text","assigneeId":"not-an-integer"}`; оба окружения | 400, тот же общий ответ, исходный текст не отражён, база прежняя | Passed, 2 случая |
| Реальный отказ SQLite после обновления задачи | Bob; перед запросом триггер `BEFORE INSERT ON Submissions` вызывает RAISE(ABORT, 's06-internal-storage-probe'); POST `/api/tasks/1/submissions`, `{"text":"s06-private-input","expectedVersion":1}`; оба окружения | 500, `{"error":"Не удалось обработать запрос."}`; нет SQL/пути/stack trace/маркеров, статус, версия и история откатились | Passed, 2 случая |
| Позитивная и регрессионная | Alice создаёт обычную задачу и задачу с названием `O'Reilly'; DROP TABLE Tasks; --` и описанием `<b>text</b><img src=x onerror=alert(1)>`, assigneeId=2; затем читает обе | 201, строки сохранены буквально, автор Alice, команда A, Assigned/version 1, таблица задач цела | Passed |
| Изоляция после записи | Dave запрашивает новые задачи команды A, сравнивается список команды B до и после создания | 404 с общей ошибкой, отказ ничего не меняет, список B прежний | Passed в составе позитивного теста |

Все ошибочные ответы проверяются на application/json и no-store. В отрицательных случаях отсутствуют маркеры Exception, System.Text.Json, Sqlite, Program.cs, полный путь базы и тестовые внутренние/пользовательские строки.

**Проверка журнала:** при сбое middleware записал `API error DbUpdateException; request <id>`. В захваченных форматированных сообщениях нет исходного bearer-токена и сданного приватного текста. Отсутствие всех внутренних диагностических сведений во всех логах не заявляется; полный производственный стек логирования этим тестом не охвачен.

## Вывод и границы

В проверенных запросах существующая реализация разделяет 400/500, не возвращает внутренние детали, сохраняет атомарность и штатное создание. Это свидетельство одного участка обработки данных, а не доказательство безопасности всего приложения.

SQL-похожая строка проверяет буквальное сохранение на этом маршруте, не все SQL-запросы проекта. JSON round-trip не доказывает безопасный DOM-вывод: отдельные DOM-проверки описаны в [M2_WEB_CHECKS](M2_WEB_CHECKS.md). Для TaskSpace не придуман endpoint вложений, отсутствующий в продукте. Новые планы rate limiting, квот, пагинации и резервирования из D-06–D-09 этими тестами не подтверждаются. Человеческая приёмка новой цепочки ещё не выполнена; существующий AI_USAGE.md не изменялся.
